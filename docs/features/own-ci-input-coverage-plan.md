# Own-CI Input Coverage Plan

Design owner: [Own-CI Input Coverage](own-ci-input-coverage.md).

1. Extend the existing workflow command with a fail-closed, sorted workflow
   inventory and the two explicit ShellCheck dialect projections. Preserve
   the existing digest-built image and zizmor execution.
2. Add positive multi-root and isolated missing/empty/symlink/native-kind
   witnesses; compare exact argv and shell inventory independently. Keep
   command failure propagation unchanged.
3. Bind the source, documentation and both standalone shell paths to the
   existing workflow requirement/command routes. Add selective-plan falsifiers
   for each shell path and check current generated fixtures remain selected.
4. Run local static checks and one independent source/spec/test review. Execute
   the native repository workflow on the exact published candidate. A missing
   bundled binary or rejected legitimate fixture is a failed qualification,
   not a reason to suppress analysis.
   The observed 1.7.12 context gap additionally requires the build-only public-API
   extension described in the design. Qualify its native string/typo/type/context
   witnesses before the unchanged real workflow inputs, and reopen a bounded
   independent control review for this newly introduced compatibility mechanism.
5. Squash-merge only after exact native gates pass. Keep further blueprint
   security, connected-boundary, capacity, shadow and omission work explicitly
   open; measure invocation cost before further CI restructuring.
