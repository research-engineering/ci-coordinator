## 3. Work Packages

### A. Dependency And Architecture Admission

- Pin deptry and Import Linter in the admitted development dependency surface.
- Configure explicit production roots; no dynamic-use exceptions are required.
- Add a small command adapter that rejects an absent or incorrect project root.
- Prove direct httpx2 import-policy parity before transferring its ownership to
  the standard protected contract; retain all unrelated custom rules.
- Preserve the native uv/npm/Go advisory matrix and qualify its machine-output
  failure/empty/unexpected-source semantics.
- Refresh the lock and exported strict-install inputs using existing owners.

Negative witnesses: missing declaration, transitive import, dev-only runtime
import, wrong/empty root, allowed integration import, forbidden external use,
tool failure, malformed/empty audit result and unrecognized package source.
Do not weaken checks with blanket ignores to make the existing repository pass.

### B. Native Test And Mutation Evidence

- Record native collection completion, module outcomes and pre/post-filter IDs.
- Derive expected candidate files independently from the declared Git universe.
- Bind expected files to the plan and each shard; reject missing/empty modules.
- Keep failure diagnostics outside the successful artifact namespace.
- Require Vitest baseline/mutant test-identity and skip parity.

Negative witnesses: module-level skip, importorskip, marker/deselection,
silent items removal, collect_ignore, narrowed filename pattern, zero tests,
collection error, foreign shard, duplicate identity, changed pending tests,
malformed report and infrastructure-only mutant failure.

Preserve exact source/run/attempt/lock correlation, coverage and the existing
named call-phase skip contract. Diagnostic publication must not relax admission.

### C. Portable Secret Scanning

- Package pinned checksum-verified Gitleaks mechanics in a reusable action.
- Scan the source tree and required base/head history with redacted output.
- Validate Git identities and distinguish tree-only from required history.
- Prevent incidental caller ignore/config files from changing admitted policy.
- Retain only explicit benign fixture exceptions with a rationale.

Negative witnesses: current-tree secret, added-then-deleted PR secret, invalid
base/head, scanner crash, modified caller ignore/config, missing report and
clean input. Do not print secret bytes in failure output or artifacts.

### D. Connected Administrator Composition

- Create an isolated real IdP/application/PostgreSQL fixture with scoped data,
  real TLS trust and no external development-service dependency.
- Use the existing economics budget-policy UI and API.
- Verify browser login, mutation, reload and retained value.
- Independently query PostgreSQL policy/audit state.
- Replay the same operation and require exactly one committed effect and audit event.
- Reject unauthenticated effect and synthetic credential/log disclosure.
- Retain bounded stage/error and log digest receipts, and destroy only owned
  resources. The connected fixture does not publish raw service/browser text.

No production endpoint, issuer, transaction or cookie relaxation is admissible.
A setup failure must remain failure. The test has its own explicit Playwright
root and cannot be silently absorbed into the existing mocked browser suite.

Implement the design's volatile-storage boundary before qualifying the revised
journey:

1. Admit a dedicated disposable GitHub-hosted Linux VM; disable global swap,
   discard core dumps through the verified `/dev/null` character device and set
   process/container core limits to zero. Refuse unsupported or shared hosts.
2. Admit two producer-owned host tmpfs mounts: 16 MiB secret/evidence root with
   `noswap,nosuid,nodev,noexec`, and nested 2 GiB runtime with
   `noswap,nosuid,nodev` and execution permitted for native temporary libraries.
   Mint synthetic credentials only after admission; do not substitute an
   ordinary temporary directory when setup fails.
3. Create every consumer directory first, then transfer ownership starting with
   the deepest children. Seed Keycloak Quarkus from the exact pinned image
   before transferring that tree to UID 1000; use `dev-mem` and RAM-backed
   data/temporary paths.
4. Apply exact per-consumer mode-0400 secret ownership, including PostgreSQL
   UID/GID 999 after `gosu`. Keep public inputs mode 0444 and preserve producer
   checkpoint/ACK access. Under browser umask 077, publish evidence only after
   explicit mode 0644 inside the validated mode-0700 evidence parent; atomic
   rename prevents the reader from observing an unreadable intermediate file.
   Inspect exact image/User, source/target/RW mounts,
   read-only rootfs, core limits, logging-none and disabled healthchecks before
   starting any consumer. HTTPS readiness receives only its CA and RAM tmp.
5. Keep the full PostgreSQL data volume and every consumer writable directory
   in admitted RAM. Preserve normal transactions, independent SQL admission and
   replay; restart retention is limited to the lifetime of the host RAM mount.
   No physical power-loss durability claim follows from this witness.
6. Qualify standard pre-start `docker start --attach` with native byte-exact
   early/multiline/blank/large/invalid-UTF-8/no-final-newline output on both
   streams and a real small-limit overflow rejection. Capture the four service
   outputs in memory, retain canary/nonempty admission, compare terminal status
   with inspected exits and reject premature completion or incomplete drain.
7. Use explicit captured PostgreSQL/HTTPS readiness probes without daemon
   health history. Keep raw logs, profiles, downloads and crash artifacts out of
   published artifacts. Remove only exact owned resources, cancel/join capture
   and unmount runtime before secret storage; report cleanup failures.

Negative witnesses include absent/foreign/non-tmpfs mounts, missing noswap,
swap or core-policy drift, extra/missing/substituted/writable secret binds,
wrong UID, pre-admission writes, missing Quarkus seed, output byte loss/overflow,
early capture completion and incomplete cleanup. Native startup and the full
business oracle must also pass under these restrictions. Source/static evidence
does not prove provider behavior, RAM sufficiency, universal copy absence or
CodeQL clearance. Do not add taint suppressions, query exclusions or dismissals.

## 4. Verification And Review

Allowed local verification is limited to current owner-admitted static
analysis, lint/format checks, no-emit type checks and bounded contract or
inventory validation. Behavioral unit/integration/browser/property/mutation
tests run through repository-owned GitHub Actions.

Review the immutable complete candidate with the repository-selected independent
reviewer. Reconcile findings against source and protected observations. Do not
rerun the expensive native aggregate between unchanged review iterations.

The final native evidence must bind the tested source/merge subject, workflow,
event, run and attempt, all required matrix occurrences and terminal results.
A stale, skipped, cancelled, partial or failed run is not acceptance.

## 5. Publication

The first PR-opening candidate is one non-merge commit over the intended base.
Publish with a product-oriented Conventional Commit title and the organization
Context / What changed / Expected result body contract. Preserve additive
history after the first provider-confirmed opening.

Creation of a PR is not merge or deployment authority. The user separately
authorizes merge if and only if the CodeQL error disappears without suppression,
ignore or dismissal and the current merge subject passes every required native
gate after independent review. Until both predicates are proved, keep the PR
unmerged even if volatile-storage risk mitigation succeeds. Rebind the current
head and completed CodeQL/provider results immediately before merge; absent
analysis or an earlier successful head is not sufficient. Deployment remains
unauthorized and CODEOWNERS deferred.
The PR must disclose remaining provider enrollment conditions without
presenting them as implemented runtime protection.
