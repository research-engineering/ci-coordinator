# Managed Check Lifetime Implementation Plan

Status: implementation plan

The [design](managed-check-lifetime.md) owns scope and semantics. This plan owns
integration order and acceptance. Reviewer selection follows repository AGENTS.

## Ordered Integration

1. Preserve installation-phase admission and controlled-participant lifecycle
   behavior. Add only their required evidence, normative and metadata owners.
2. Register the finite nine in the existing named-suite runner; retain exact
   ordered IDs, single patches, valid baselines and mandatory matrix execution.
3. Retain per-phase source/manifest/patch/XML/output identities before overwrite
   or cleanup. Capture failure must suppress aggregate success independently of
   the unchanged kill classifier. Allocate one fresh bounded invocation below
   the fixed suite root for each opted-in run; all18 phase records and the
   summary must bind to it. Preserve earlier runs and reject duplicate phases
   only within the same invocation. No default suite acquires capture effects.
4. Bind requirement routes and required tuples, exact argv, native matrix and
   execution envelopes. Add missing explicit runtime028 selectors without
   deleting any existing selector or weakening complete native collection.
5. Refresh derived sources through their existing generator, then recheck source
   conservation, routes, source hashes, scopes and every changed budget ancestor.
6. Integrate the current default-branch contracts with the executable-entry
   wrappers. Preserve complete text-policy composition, sys.prefix-bound
   executable resolution and existing native process diagnostics; rebind all
   resulting source hashes before qualification.
7. Qualify the exact integrated commit through existing GitHub routes. No local
   behavioral or mutation run is an alternative to that qualification.

Retain the existing portable command emitter through the Dev Container success
boundary. Qualify its bounded diagnostic projection with exact ordered positives,
isolated invalid observations, primary/cancellation preservation and unchanged
provider calls. Inspect real native framing before attributing any measured cost
to a particular command; missing diagnostics do not weaken the proof population.

## Evidence And Native Gates

The new suite uses a 300000 ms per-invocation cap, inherited from the existing
runtime028 command allowance. Nine baselines and nine mutants plus the existing
60000 ms suite reserve require 5460000 ms. Existing inner deadlines and stop
allowances do not change. Branch-head sums include every existing child plus
the new suite and unchanged orchestration reserve. The direct matrix retains
its existing job cap and reserve. These are budgets, not measured timing claims.

Native prerequisites are pinned Python, locked backend dependencies, Git and
Node24.21.0. A missing or wrong prerequisite invalidates the baseline. The suite
uses direct pytest commands, preserving the existing JUnit selection and
setup/call/teardown admission. Its artifact upload is always attempted only for
this suite and retains ignored mutation evidence for seven days.

Read the retained XML at the exact manifest node and phase, matching its digest
and source/patch binding. A setup/import/network failure, missing ready marker,
outer timeout, cleanup error or unrelated assertion is not a causal kill.
The automated classifier is not an assertion matcher; manual finite admission
does not close general TEST6. No survivor or invalid witness is accepted.

Keep current public/managed positives, private operand negatives, real accepted
child setup/exit cuts, callback, caught-error recovery, repeated first-time,
physical group absence, no-next-command, phase/export and lease controls.
Keep A3 public dispatch/entry/terminal conservation and the managed receiverless
negative. Historical unmanaged end-to-end remains unexecuted, not waived into
a claim. Supervisor signal exit, child terminal marker and physical child exit
remain independent observations in the native fixture.

## Static And Final Barriers

Static admission covers literal suite inventory, single patch applicability,
capture path/identity/missing/overflow/default-off controls, exact routes and
required tuples, command/matrix equality, unchanged required guards, budget
closure, documentation reachability, types/lint and generated-source freshness.
Behavioral tests for those contracts still run only in GitHub.
Invocation controls additionally require two successful consecutive complete
runs without shared receipts at equal and changed source revisions, safe
concurrent allocation, exclusive collision refusal and rejection of foreign
invocation records by the aggregate gate.

Retain the reviewed source manifest through actual-base integration and explain
each required overlap. Freeze the complete new source and derived manifest. Missing
capture, changed inputs, unexpected platform failure or a new lifecycle semantic
dependency blocks qualification and requires a bounded root decision; never
extend grace, strip private context, change an expected failure or relax a gate
to turn such an outcome into success.
